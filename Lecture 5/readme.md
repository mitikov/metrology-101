# Завдання 1: Python Challenge — Три різні підсумки

## Специфікація

* **Вхідні дані:** три окремі списки внесків, уже приведених до тиску й виражених у кПа:
  * невід'ємні межі модулів похибок `bounds`;
  * невід'ємні стандартні відхилення випадкових внесків `sigmas`;
  * знакові оцінки систематичних зміщень `biases`.
* **Навчальні дані:**
  * `bounds = [0.12, 0.08, 0.05]`;
  * `sigmas = [0.03, 0.04, 0.02]`;
  * `biases = [-0.06, 0.02]`.
* **Припущення для `sigmas`:** випадкові внески незалежні й мають скінченні дисперсії.
* **Вихідні дані:** три окремо підписані результати `bound_total`, `sigma_total`, `bias_total` та одиниця `kPa`.
* **Інструменти:** базовий Python, `sum`, модуль `math`.

---

## Опис задачі

Створіть окремі функції `bound_sum(bounds)` та `rss(sigmas)`. Додатково обчисліть алгебраїчну суму оцінок зміщень. Списки описують **різні характеристики**, тому об'єднувати їх перед розрахунком не можна.

Якщо для кожного внеску відомо лише $|e_i|\le B_i$, гарантована за заданими межами оцінка суми:

$$B_\Sigma = \sum_i B_i.$$

Для незалежних випадкових внесків стандартне відхилення суми:

$$\sigma_\Sigma = \sqrt{\sum_i \sigma_i^2}.$$

Знакові оцінки зміщень складаються алгебраїчно:

$$b_\Sigma = \sum_i b_i.$$

Можлива компенсація відомих зміщень не означає, що можна віднімати одну невідому межу від іншої. Нормальність не потрібна для самого RSS за незалежності й скінченних дисперсій; вона знадобиться для окремих висновків про ймовірність покриття.

---

## Критерії валідації й розрахунку

1. **Числові дані:** відхиляйте текст, `None`, логічні значення, `NaN` та нескінченність. Для перевірки скінченності використайте `math.isfinite`.
2. **Знак:** межі й СКВ не можуть бути від'ємними. Зміщення можуть мати будь-який знак; не застосовуйте до них `abs()` перед складанням.
3. **Порожній список:** у цій вправі відхиляйте його зі зрозумілим повідомленням. Відсутність описаних внесків не підтверджує нульової похибки каналу.
4. **Незалежність:** використовуйте `rss` для заданого незалежного списку. За невідомого зв'язку між внесками не оголошуйте RSS обґрунтованим СКВ суми.
5. **Контрольні випадки:** один внесок; один нульовий внесок; перестановка елементів; від'ємна межа; від'ємне СКВ. Перестановка не повинна змінювати результат.
6. **Незмінність даних:** не змінюйте первинні списки й не округлюйте проміжні результати.

> **Одиниці та зміст:** усі три підсумки подаються у кПа, але `bound_total` — межа, `sigma_total` — СКВ, `bias_total` — знакова оцінка зміщення. Однакова одиниця не робить їх взаємозамінними.

**Що здати:** функції, результати для навчальних даних, контрольні випадки та 3–5 речень про відмінність трьох підсумків.

# Завдання 2: Python Challenge — Паспортна межа у словнику

## Специфікація

* **Вхідні дані:** показ напруги `x` у V та словник навчальної специфікації:

```python
spec = {
    "mode": "DC",
    "range": 10.0,
    "a": 0.002,
    "d": 3,
    "q": 0.001,
    "unit": "V",
    "other_conditions_met": True,
}
values = [0.2, 5.0, 9.8]
```

* **Область чинності у вправі:** режим DC, показ від 0 до 10 V включно; інші паспортні умови прийнято виконаними.
* **Вихідні дані:** для кожного показу словник із полями `x`, `mode`, `bound`, `relative_bound_percent`, `unit`, `status`, `notes`.
* **Походження параметрів:** числа навчальні; це не паспорт конкретної моделі мультиметра.

---

## Опис задачі

Створіть функцію, що приймає показ, фактичний режим вимірювання та словник специфікації. Спочатку перевірте область чинності, потім обчисліть межу:

$$B(x)=a\,|x|+d\,q.$$

Тут `a` — безрозмірна **частка** показу, `d` — кількість одиниць молодшого розряду (counts), `q` — крок показу на вибраному діапазоні у V. Значення `0.002` означає 0,2%, а не 0,002%.

Для ненульового показу додатково обчисліть відносну межу:

$$B_{\mathrm{rel}}(x)=\frac{B(x)}{|x|}\cdot100\%.$$

Сформуйте по одному рядку звіту для трьох навчальних показів. Збережіть разом із числом режим, одиницю та припущення щодо інших умов.

---

## Критерії валідації й перевірки

1. **Повнота специфікації:** перевірте наявність усіх потрібних полів. Відсутній крок або невідомий режим не замінюйте мовчки нулем чи типовим значенням.
2. **Числові параметри:** показ і параметри мають бути скінченними числами; `range > 0`, `a ≥ 0`, `q > 0`, `d` — невід'ємне ціле число. Логічні значення не є числовими параметрами.
3. **Діапазон:** за `x < 0` або `x > range` поверніть `status = "out_of_range"` та `bound = None`. Інтервал 0–10 V заданий умовою цієї вправи, а не загальним правилом для всіх DC-вимірювань.
4. **Режим:** фактичний режим має збігатися з `spec["mode"]`. Для AC за цією DC-специфікацією поверніть `status = "mode_mismatch"` і не видавайте чинну межу.
5. **Інші умови:** за `other_conditions_met = True` поверніть `status = "valid_under_assumptions"`. Якщо це поле відсутнє, хибне або не підтверджене, не оголошуйте межу чинною: `bound = None`, статус із поясненням непідтверджених умов.
6. **Нульовий показ:** обчисліть абсолютну межу за формулою, але поверніть `relative_bound_percent = None` і поясніть ділення на нуль.
7. **Контрольні випадки:** `x = 0`, `x = 10`, `x = 10.1`, режим AC, відсутнє поле `q`, неправильні одиниці. У цій функції всі напруги задані у V; значення у mV потребують явного перетворення до виклику.

> **Не змішуйте характеристики:** `B(x)` є межею модуля похибки за умовами специфікації, а не знаком фактичної похибки та не СКВ. Не додавайте ще раз «пів кроку дисплея» без перевірки, чи цей ефект уже охоплено паспортною межею.

**Що здати:** функцію, таблицю для трьох показів, контрольні випадки та пояснення, які умови перевірила програма, а які прийнято виконаними.

# Завдання 3: Python Challenge — Основна й додаткова температурна межі

## Специфікація

* **Навчальні параметри:**
  * `B0 = 0.20` кПа;
  * `kT = 0.015` кПа/°C;
  * нормальний інтервал `normal = (18.0, 28.0)` °C;
  * робочий інтервал `working = (-10.0, 60.0)` °C;
  * температури `temperatures = [20.0, 28.0, 35.0, 60.0, 65.0]` °C.
* **Вихідні дані:** для кожної температури словник із полями `temperature`, `distance_to_normal`, `temperature_bound`, `total_bound`, `status`.
* **Модель:** параметри навчальні; температурна межа лінійно зростає лише поза нормальним інтервалом і лише в межах робочих умов.

---

## Опис задачі

Створіть функцію, яка спочатку перевіряє робочі умови. Якщо вони виконані, визначте відстань до **нормального інтервалу**, а не до нуля температурної шкали й не завжди до нижньої межі:

$$d_T=\max(T_{\min}-T,\;0,\;T-T_{\max}).$$

Тут $T_{\min}$ і $T_{\max}$ — межі **нормального** інтервалу. Потім обчисліть:

$$B_T=k_T\,d_T,$$

$$B=B_0+B_T.$$

Усередині нормального інтервалу `dT = 0`. За його межами, але всередині робочого інтервалу, з'являється додатковий внесок. Ця модель описує межу можливого відхилення, а не відому знакову температурну поправку.

---

# Завдання 4: Python Challenge — Узгоджений бюджет вимірювального каналу

## Специфікація

* **Вхідні дані:** список словників із внесками, уже приведеними до спільної вихідної напруги; опис припущень і перелік ефектів, охоплених основною межею.
* **Поля внеску:** `effect_id`, `category`, `kind`, `value`, `unit`.
* **Тип характеристики `kind`:** `"bound"` — межа; `"stdev"` — стандартне відхилення.
* **Навчальні дані:**

```python
contributions = [
    {"effect_id": "basic",       "category": "basic",       "kind": "bound", "value": 12.0, "unit": "mV"},
    {"effect_id": "temperature", "category": "temperature", "kind": "bound", "value": 8.0,  "unit": "mV"},
    {"effect_id": "dynamic",     "category": "dynamic",     "kind": "bound", "value": 6.0,  "unit": "mV"},
    {"effect_id": "loading",     "category": "loading",     "kind": "bound", "value": 4.0,  "unit": "mV"},
    {"effect_id": "sensor_noise", "category": "random",     "kind": "stdev", "value": 2.0,  "unit": "mV"},
    {"effect_id": "reader_noise", "category": "random",     "kind": "stdev", "value": 3.0,  "unit": "mV"},
]

assumptions = {
    "independent": True,
    "normal_random_sum": True,
    "sigmas_known": True,
    "operating_conditions_met": True,
}
covered_by_basic = []
k = 1.96
```

* **Вихідні дані:** звіт із полями `bound_total`, `sigma_total`, `model_bound`, `unit`, `status`, `checks`, `notes`.
* **Умова:** для початкового прикладу внески описують різні ефекти; основна межа не включає окремо зазначені температуру, динаміку, навантаження й шумові внески. Числові параметри навчальні.

---

## Опис задачі

Зберіть функції попередніх задач у звіт, який розділяє характеристики та перевіряє узгодженість бюджету.

1. Перевірте структуру рядків, значення, одиниці й ідентифікатори ефектів.
2. Розділіть рядки за `kind`.
3. Обчисліть граничну суму лише для `bound`:

$$B_\Sigma=\sum_i B_i.$$

4. За підтвердженої незалежності обчисліть СКВ суми лише для `stdev`:

$$\sigma_\Sigma=\sqrt{\sum_j\sigma_j^2}.$$

5. Лише за додатково прийнятої нормальності випадкової суми та відомих СКВ обчисліть модельну величину:

$$L=B_\Sigma+k\sigma_\Sigma.$$

У моделі $\Delta=b+\varepsilon$ та $|b|\le B_\Sigma$ ця величина задає межу модуля повної похибки з імовірністю щонайменше приблизно 95% за нульового середнього нормальної випадкової суми й `k = 1.96`.

Це **не довірчий інтервал середнього з вибірки** і не гарантована межа для всіх можливих реалізацій. Якщо СКВ оцінено за короткими серіями, використання множника 1,96 із заявленим покриттям потребує окремого обґрунтування.

---

## Критерії узгодженості й звіту

1. **Повні рядки:** кожен внесок має всі потрібні поля. Невідомий тип характеристики відхиляйте, а не включайте за замовчуванням до однієї із сум.
2. **Значення:** `value` — скінченне невід'ємне число; `k` — скінченне додатне число. Текст, `None`, логічні значення, `NaN` і нескінченність не є внесками.
3. **Одиниці:** у цій вправі приймайте лише спільну одиницю `mV`. Рядок у V не можна додавати без явного перетворення. За невідповідності поверніть помилку валідації, а не чинний числовий бюджет.
4. **Повтор ідентифікатора:** однаковий `effect_id` у двох рядках означає конфлікт. Не додавайте обидва й не видаляйте один мовчки; поверніть статус конфлікту та його опис.
5. **Перекриття основної межі:** якщо `effect_id` окремого внеску входить у `covered_by_basic`, повідомте про подвійне врахування. Наприклад, додайте внесок `quantization` та задайте `covered_by_basic = ["quantization"]`. Не підтверджуйте такий бюджет як узгоджений.
6. **Невідома залежність:** якщо `independent` не підтверджено, для валідних граничних рядків збережіть `bound_total`, але поверніть `sigma_total = None` та `model_bound = None`. Поясніть, що для випадкової суми потрібні відомості про зв'язки або коваріації.
7. **Непідтверджена нормальність або невідомі СКВ:** за підтвердженої незалежності RSS може бути обчислено, але `model_bound = None`. Зазначте, яка передумова ймовірнісного висновку відсутня; вибіркові оцінки не називайте відомими СКВ.
8. **Умови роботи:** за непідтверджених робочих умов не повертайте бюджет як чинну характеристику каналу. Використайте статус `conditions_not_confirmed`; чинні підсумки — `None`.
9. **Початковий коректний випадок:** за виконаних перевірок поверніть `status = "consistent_under_assumptions"`. У `checks` перелічіть перевірки, у `notes` — прийняті припущення.
10. **Первинні дані:** не змінюйте список і словники внесків. Порожній бюджет відхиляйте; відсутність опису не є підтвердженням нульової похибки.

| Непідтверджена нормальність | normal_random_sum = False | RSS є за незалежності, модельної межі немає |
| Умови невідомі | operating_conditions_met = None | Відсутність чинного бюджету |

Для коректного початкового випадку додатково приведіть `bound_total`, `sigma_total` та `model_bound` до тиску за чутливості `S = 0.1 В/кПа`. Спочатку переведіть mV у V, потім поділіть на S. Збережіть назви характеристик і одиницю кПа.

> **Перевірка повноти:** програма може знайти лише явно описані конфлікти. Вона не знає автоматично, що входить у реальну паспортну межу, чи дотримані умови навантаження та чи не пропущено спільне джерело впливу. Ці відомості потрібно отримати з документації й моделі каналу.

**Що здати:** функцію звіту, результат початкового випадку у mV та кПа, контрольні сценарії й короткий висновок про область чинності бюджету.
